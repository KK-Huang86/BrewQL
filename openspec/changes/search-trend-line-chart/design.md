## Context

第一張圖表與第一批行為資料。資料只用模擬值（不含任何真實 Find Coffee 使用者資料），圖表由後端依結果形狀決定，前端只負責畫。

## Goals / Non-Goals

**Goals:** 問「最近半年不限時的搜尋量趨勢」看到有考試季高峰的折線圖；圖表選擇規則可測、可預期。

**Non-Goals:** 長條圖、多條線（ticket 7、之後）；讓模型決定圖表類型；使用者自選圖表。

## Decisions

### D1. 搜尋紀錄以建庫當天為基準
`search_logs` 的時間 = 建庫當天 − 由固定種子產生的天數偏移（0～182 天）。分布形狀每次重建相同，只隨建庫日期平移，「最近半年」永遠有資料。評估的參考 SQL 在執行當下計算，不受平移影響。代價：不同日期建的資料庫，逐筆日期不同。

### D2. 考試季效應用權重產生
5、6、11、12 月的搜尋，`filters` 同時含「不限時」與「插座」的機率較高。`filters` 只放使用者勾選的條件，鍵為布林：`no_time_limit`（不限時）、`has_socket`（有插座）、`pet_friendly`（寵物友善），例如 `{"no_time_limit": true, "has_socket": true}`；工作友善的搜尋以 `filters @> '{"no_time_limit": true, "has_socket": true}'` 判斷。任何 6 個月的區間都同時含考試季與非考試季月份，所以檢查永遠可比較。

### D3. 圖表由後端依結果形狀決定
規則確定、可單元測試，也不多花模型 token。`chart` 放在 API 回應，前端看到不認得的類型就只顯示表格。

### D4. x 軸接受 ISO 格式文字
模型常用 `to_char(..., 'YYYY-MM')` 產生月份（例如評估的 q09）。只接受 `YYYY-MM` 與 `YYYY-MM-DD` 兩種固定格式，其他文字（行政區名稱）仍是表格。

### D5. 新資料表進白名單與唯讀角色
`users`、`search_logs`、`v_daily_activity` 加入 SQL 防護白名單，`genbi_reader` 只授予 SELECT。schema 說明補欄位意義與時間用語（「最近半年」= 今天往回 6 個月）。

### D6. Guardrail 的營運數據涵蓋會員與搜尋
實測（4.2 前）「最近半年每個月不限時的搜尋量」被輸入 Guardrail 以 `topic:off-topic` 擋下：拒絕話題定義只寫「咖啡店營運數據」，搜尋紀錄被當成無關。第一次改為「不是 Find Coffee 營運數據（咖啡店、會員、搜尋）的請求」，版本 2 仍擋下：主題分類器不擅長「不是 X」這種否定定義。改為正面列舉要擋的類型（創作、閒聊、寫程式、個人建議、天氣新聞娛樂、要求改變角色或忽略指示）；不在列舉中的無關問題通過 Guardrail，由模型以 refuse 拒答，仍是兩層防護。修改 policy 會發布新版本（舊版本保留），API 更新 `BEDROCK_GUARDRAIL_VERSION` 後才生效。

## Risks / Trade-offs

- [模型用 `date_trunc` 回傳 timestamp 或用文字月份] → 兩者都畫成折線圖（D4）
- [建庫日期不同造成數字不同] → 故事檢查只驗證規模與比例，不驗證逐筆數值
